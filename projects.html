Asynchronous FIFO Design

A robust, parameterizable Asynchronous FIFO handling Clock Domain Crossing (CDC) safely using Gray code pointers and synchronizers.

Architecture Block Diagram

         +---------+                                   +---------+
         |         |--- wdata(N-1:0) --->|   Memory    |---> rdata(N-1:0)
  wclk ->|  Write  |                     |  (DPRAM)    |
 winc  ->| Control |--- waddr(M-1:0) --->|             |<--- raddr(M-1:0) <- rclk
         |         |--- wclken --------->|             |<- rinc

           |     ^                                     ^     |

Key Implementation Details

The design ensures safe data transfer across independent clock domains by converting binary pointers to Gray code before passing them through a 2-stage synchronizer flip-flop chain. This prevents multi-bit transition errors during CDC.

Verilog Implementation Snippet

Binary to Gray Code Conversion and Pointer Logic:


module wptr_full #(parameter ADDRSIZE = 4) (
    output reg wfull,
    output     [ADDRSIZE:0] wptr,
    output reg [ADDRSIZE:0] wq2_rptr,
    input      [ADDRSIZE:0] rq2_wptr,
    input      winc, wclk, wrst_n
);

    reg  [ADDRSIZE:0] wbin;
    wire [ADDRSIZE:0] wgraynext, wbinnext;
    wire wfull_val;

    // Binary pointer next state
    assign wbinnext  = wbin + (winc & ~wfull);

    // Gray pointer next state
    assign wgraynext = (wbinnext >> 1) ^ wbinnext;

    // Pointer update
    always @(posedge wclk or negedge wrst_n) begin
        if (!wrst_n) {wbin, wptr} <= 0;
        else         {wbin, wptr} <= {wbinnext, wgraynext};
    end

    // Full condition logic (MSB !=, 2nd MSB !=, rest ==)
    assign wfull_val = (wgraynext == {~wq2_rptr[ADDRSIZE:ADDRSIZE-1],
                                       wq2_rptr[ADDRSIZE-2:0]});

    always @(posedge wclk or negedge wrst_n) begin
        if (!wrst_n) wfull <= 1'b0;
        else         wfull <= wfull_val;
    end
endmodule
Verification • SystemVerilog / UVM

ALU Block-Level UVM Testbench

A comprehensive Universal Verification Methodology (UVM) testbench designed to exhaustively verify an Arithmetic Logic Unit using constrained-random stimuli and functional coverage.

Verification Plan & State Table

The verification plan targets 100% functional coverage across all supported opcodes, corner cases (overflow, zero flag), and sequential operation modes.

Opcode [3:0] Operation Coverage Target focus
0000 ADD MAX_VAL + 1 (Overflow), Negative + Positive
0001 SUB A < B (Negative result), MIN_VAL - 1 (Underflow)
0100 AND Walking 1s, Walking 0s, All 0s, All 1s
1000 SHIFT_L Shift by 0, Shift by MAX_WIDTH, Shift out 1s

UVM Sequence Item & Constraints

Defining the transaction level model with constraints to hit corner cases effectively. 


class alu_seq_item extends uvm_sequence_item;

  // Randomize transaction variables
  rand bit [31:0] a;
  rand bit [31:0] b;
  rand bit [3:0]  opcode;

  // Output variables (not randomized)
  bit [31:0]      result;
  bit             zero_flag;
  bit             carry_flag;

  // UVM Factory Registration
  `uvm_object_utils_begin(alu_seq_item)
    `uvm_field_int(a, UVM_ALL_ON)
    `uvm_field_int(b, UVM_ALL_ON)
    `uvm_field_int(opcode, UVM_ALL_ON)
    `uvm_field_int(result, UVM_ALL_ON)
  `uvm_object_utils_end

  function new(string name = "alu_seq_item");
    super.new(name);
  endfunction

  // Constraint: Focus on addition and subtraction frequently
  constraint op_c {
    opcode dist {
        4'b0000 := 30, // ADD
        4'b0001 := 30, // SUB
        [4'b0010:4'b1111] :/ 40 // Others
    };
  }

  // Constraint: Generate interesting corner cases for inputs
  constraint data_c {
    a dist {
        32'h0000_0000 := 10,
        32'hFFFF_FFFF := 10,
        [32'h0000_0001:32'hFFFF_FFFE] :/ 80
    };
  }
endclass
