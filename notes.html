# Technical Notes & Engineering Insights

Setup & Hold Time Violations

Digital Logic & Timing Analysis

What are Setup & Hold Times?

  • Setup Time: Minimum duration the data signal must remain stable BEFORE the active clock edge.
  • Hold Time: Minimum duration the data signal must remain stable AFTER the active clock edge.

Violations & Fixes:

  • Setup Violation (Data too slow): Caused by long combinational path delays or high clock frequency. Fix by pipelining critical paths or reducing clock frequency.
  • Hold Violation (Data too fast): Caused by short combinational paths overwriting data too early. Fix by inserting delay buffers along the data path (cannot be fixed by changing clock frequency).

Clock Domain Crossing (CDC) & Metastability:

  • Crossing asynchronous clock domains inevitably violates setup/hold times at destination registers, causing metastability.
  • Fix: Use a 2-stage Flip-Flop Synchronizer (2-FF) to allow metastable signals time to settle before downstream logic samples them.

Common Verilog Pitfalls: Unintended Latches

RTL Design & Verilog

The Problem:

In combinational blocks (always_comb), if an output variable is not assigned a value in every possible execution path (e.g., missing else branches or incomplete case statements), the synthesis tool infers a hardware LATCH to hold its previous value. Latches waste area, introduce timing issues, and create glitched feedback paths.

Incorrect Code (Infers Latch):

always_comb begin
    if (enable) begin
        out = data_in;
    end
    // Latch inferred! 'out' must hold value when enable == 0
end

Correct Code (Default Assignment):

always_comb begin
    out = 1'b0; // Default assignment prevents latch inference
    if (enable) begin
        out = data_in;
    end
end

Asynchronous FIFO & Clock Domain Crossing (CDC)

Computer Architecture & CDC

The Challenge:

An Asynchronous FIFO passes data between independent clock domains (Write Clock vs. Read Clock). Read and Write pointers must be compared across domains to check for Full or Empty conditions.

Why Binary Pointers Fail:

Multi-bit binary counters toggle multiple bits simultaneously (e.g., 3'b011 to 3'b100 toggles 3 bits). If the destination clock samples during a transition, intermediate metastable states (like 3'b111 or 3'b000) cause false Full/Empty triggers or data corruption.

The Solution: Gray Code Encoding:

Gray Code guarantees that ONLY ONE bit changes on any single increment (e.g., 2'b01 -> 2'b11 -> 2'b10). Passing Gray Code pointers through a 2-FF synchronizer ensures the receiving domain samples either the valid old pointer or valid new pointer—never a corrupted intermediate state.
